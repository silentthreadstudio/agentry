spec Session middleware + token refresh

Job to be done

A signed-in user should stay signed in across a token expiry without noticing, and an expired refresh token should end the session cleanly rather than looping.

Acceptance criteria

  • AC1 — a request with an expired access token but a valid refresh token succeeds, and issues a new pair.
  • AC2 — a request with an expired refresh token returns 401 and clears the session cookie.
  • AC3 — concurrent requests during a refresh do not each trigger their own refresh.
you · on “an expired refresh token…” — should this redirect, or just 401 and let the client decide?
conductor · 401 only. Redirecting from an API couples it to one client.
✦ Recalled memory · shaped this spec
Concurrent refresh needs a single-flight lock — the last time this shipped without one, every parallel request minted a new token pair and invalidated the others.
