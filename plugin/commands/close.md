---
description: Close the session the same way every time — the owner's pending decision drafts, board fix, worktree and process cleanup (asks before applying), episodes for finished lanes, a short judgment note, and the handoff with the resume line.
---

Close the session. Run `agentry lane` and `agentry board` from the main checkout, in the foreground. The details of every field: the `conducting` skill's `references/session.md`.

Shell calls use `agentry`, the plugin's `bin/` command; where it is not on PATH, run `node "${CLAUDE_PLUGIN_ROOT}/scripts/board.mjs"` (or `lane.mjs`) with the same arguments.

1. Run `agentry lane session close`. It prints one JSON object and writes nothing: `drafts`, `fixPlan`, `ledgers`, `cleanable`, `strays`, `leftAlone`, `unknown`, `warnings`, `diskFree`, `episodesPending`, `note` (when the note file exists) and, when the workflow file names `extensions.start.checks` or `extensions.close.checks`, `checks`.
2. **Drafts.** Re-read the session for owner calls that were never drafted and run `agentry board draft add` for each (the `process` skill's `references/drafts.md`). Then show every pending draft (`agentry board draft list`, and `agentry board draft apply <n>` for what one would write) and ask the owner to OK, drop or correct it. Run `agentry board draft apply <n> --apply` only on that draft's OK; a correction goes in the same call (`--answer "<text>"`, and `--why "<text>"` for a decision), kept on the draft as edited, with no drop and re-add.
3. **Board.** If `fixPlan` lists fixes (it is `agentry board fix` without `--apply`: what it would write), run `agentry board fix --apply` and show what it wrote. Show what it leaves for the owner, each with its command.
4. **Sweep.** Show `cleanable`, `strays`, `leftAlone`, `unknown` and `warnings` (low disk, or no `lsof`, is a warning to say, not to fix). Ask the owner before `agentry lane sweep --apply`, and say what it will remove and stop. Unknown worktrees are listed, never removed; a `leftAlone` process is an interactive shell (a terminal, a login shell) that sits in a merged worktree: sweep never signals it, so tell the owner to leave that directory. `--apply` exits 1 if a process or a worktree is still there; say which.
5. **Episodes.** For each id in `episodesPending`: `agentry lane exec close <id>`, call `episode_write` with the episode it prints, then `agentry lane exec close <id> --episode <the id it returns>`.
6. **Checks.** For each skill in `checks.close.named` (`extensions.close.checks`): run its `## Close` or `## End` section, or the whole skill when it has none, then record the outcome with `agentry lane session close --check <skill>=pass|fail --note "<one line>"`. A skill in `checks.close.missing` has no `SKILL.md`: say so and point to `/agentry:init`. A commit or push step in such a skill is the owner's: close never commits.
7. **Note.** When `note.stale` is set (`why: "now-changed"`: the Now it was written under is gone; `"ids-done"`: every id it names is done) or `note.old` is true (12 h old or more, by the file's mtime), ask the owner "rewrite or clear the note?" before writing. A rewrite, or a note that is neither, is written as follows; a clear deletes the note file and writes none. Write the judgment note to the board's note file (`status.note` in the process file, default `.agentry/NOTE.md`): at most 10 lines, what a cold reader needs that the board does not say (decisions leaning, risks, what you would do next). It replaces the previous note. No status table: status is derived.
8. **Hand off** in a few lines: what landed, what is still open, drafts left, each close check that failed and each still pending (`checks.close.failed`, `checks.close.pending`), and the resume line `/agentry:start`.

Never edit board files by hand, never commit or push, never apply a draft or a sweep without the owner's OK.
